### 🐛 主要 Bug 修复

#### 问题 1: 错误响应格式不一致
**发现时间**: 测试 MCP 工具时

**问题描述**:
- 部分错误返回路径使用字符串作为错误内容
- 部分错误返回路径使用字典结构
- 导致测试代码尝试访问 `data['error']['message']` 时失败，因为 `data['error']` 可能是字符串

**受影响的代码位置** (修复前):
```python
# mcp_server.py 多个位置
return create_tool_response(
    f"Node hub path not found: {hub_path}",  # ❌ 返回字符串
    success=False
)
```

**修复方案**:
标准化所有错误响应为统一的字典结构：
```python
return create_tool_response(
    {
        "type": "NODE_HUB_ERROR",
        "message": f"Node hub path not found: {hub_path}"
    },
    success=False
)
```

**修复的具体位置**:
1. `handle_get_node_info()` - 节点库路径不存在 (lines 306-312)
2. `handle_get_node_info()` - 节点包不存在 (lines 319-325)
3. `handle_validate_yaml()` - YAML 文件不存在 (lines 393-399)
4. `handle_edit_yaml()` - YAML 文件不存在 (lines 551-557)
5. `handle_run_runtime()` - YAML 文件不存在 (lines 613-619)
6. `handle_read_logs()` - node_id 缺失 (lines 656-662)
7. `call_tool()` - 未知工具 (lines 275-281)

**验证结果**:
- ✅ 创建了专门的测试文件 `test_error_responses.py`
- ✅ 测试了 7 种错误场景，全部通过
- ✅ 所有错误响应现在都返回一致的 JSON 结构：

  ```json
    "timestamp": 1234567890.0,

  }
  ```

### 🎯 错误类型标准化

现在系统使用以下标准化错误类型：

| 错误类型 | 使用场景 | 示例 |
|---------|---------|------|
| `NODE_HUB_ERROR` | 节点库路径问题 | 节点库目录不存在 |
| `NODE_NOT_FOUND` | 节点包查找失败 | 指定的节点包不存在 |
| `FILE_NOT_FOUND` | 文件不存在 | YAML 配置文件未找到 |
| `INVALID_INPUT` | 参数验证失败 | 缺少必需参数 |
| `NODE_INFO_ERROR` | 节点信息查询异常 | 加载 manifest 失败 |
| `VALIDATION_ERROR` | YAML 验证异常 | 配置格式错误 |
| `EDIT_ERROR` | YAML 编辑异常 | 无法写入文件 |
| `TOOL_ERROR` | 工具执行异常 | 未预期的运行时错误 |
| `UNKNOWN_TOOL` | 工具不存在 | 调用了未定义的工具 |
