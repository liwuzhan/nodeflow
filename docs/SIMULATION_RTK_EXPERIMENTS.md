# 仿真闭环与纯 RTK 直线复现实验

连续旋耕的大半径回转、螺旋候选及整田闭环结果见 [连续旋耕规划器](CONTINUOUS_TILLAGE_PLANNERS.md)。

本轮把仿真器从路径展示工具推进为可重复的闭环实验工具。主要用途是检查车辆真实运动、RTK 观测、滤波、选点和转向指令之间的关系，尤其是“指令要走直线，车辆却左右摆动”的现象。

实现基于 `7c0c559` 的项目结构，开发分支为 `feat/simulation-rtk-reproduction`。实验中的噪声和响应时间都是合成参数；没有用实车记录辨识，也没有由此修改实车控制增益。

## 1. 本轮完成的行为

| 部分 | 现在的行为 |
|---|---|
| 车辆运动 | 速度与油门模式明确切换，零速度不会恢复旧油门；两种模式统一限速、线/角加速度约束；可配置速度和转向的一阶响应时间 |
| 角度与历史 | 修正跨越 ±π 的位置积分，历史航向走短弧；插值保留机具等完整状态 |
| 采样 | 仿真时间驱动传感器采样，查询只返回缓存；样本带采集时间与序号，同一样本不会因为读取次数不同而改变 |
| RTK | 可独立控制定位噪声、航向噪声、频率、传输延迟及定位状态；默认按双天线独立航向建模，不把“纯 RTK”直接等同于单天线 |
| 重置 | 独立随机序列；清除旧命令、机具目标、延迟队列和历史，同种子重播 |
| 通信 | REQ 超时后重建连接；未确认指令保留重试，超龄运动指令替换为停车；停车失败不能算成功 |
| 服务端断流 | 运动和机具分别检查最后命令年龄，默认 0.5 秒；停车/抬起指令仍经过车辆响应模型 |
| 机具衔接 | 仿真图等待实际悬挂/PTO 反馈到位后前进；终点目标 `final` 与实际到达 `arrived` 分开 |
| 作业中转向 | 作业意图要求落刀时，不再隐式原地转向；几何不可跟踪时返回 `needs_reposition`。这不是自动生成新掉头路线 |
| 覆盖评价 | 累计实际机具扫掠，统计唯一覆盖、遗漏、重复和田外面积，扣除孔洞；显示窗口裁剪不再重置统计 |

这些仍是二维差速/履带运动学和几何模型。机具刚性跟随车辆朝向，可设纵向偏置；没有模拟铰接拖挂、土壤力、液压压力和 GNSS 射频环境。

## 2. 最小可重复直线实验

仓库根目录运行：

```bash
python3 -m pip install -r simulation/requirements.txt
python3 -m simulation.rtk_experiment --output /tmp/nodeflow-rtk-experiment

# 只比较组合场景与去除延迟后的场景
python3 -m simulation.rtk_experiment \
  --scenario combined --scenario combined_no_delay \
  --seed 23 --output /tmp/nodeflow-rtk-seed23
```

配置在 [rtk_straight.yaml](../simulation/experiments/rtk_straight.yaml)。输出包含：

- 每场景 CSV：真实位置、原始/滤波 RTK、采样时间及年龄、目标点、速度和转向指令、控制状态。
- 每场景 JSON 与 `summary.json`：完整实验参数、采用的控制/滤波/选点参数、源文件哈希、结果指标。
- `comparison.png`：各场景的真实横向误差、转向指令和采样年龄。
- `observations.png`：组合场景的观测与真实运动、转向指令与实际响应；只选其他场景时画最后一个。

复现实验调用现有节点算法：`EMAFilter → transform_pose → compute_progress → WaypointSelector → compute_velocity_cmd`，车辆由同一个 `SimulatorServer.step_once()` 推进。滤波、选点和控制参数从 `planning_simulation.yaml` 读取，IMU 融合明确关闭。

这是按固定顺序调度的单进程实验：物理 100 Hz、控制 50 Hz、RTK 与桥接读取 20 Hz。重复读取不会重复滤波。它不包含操作系统调度、SharedBuffer 丢帧或 TCP 排队；这些需要另外运行多进程图检查。直线实验将机具保持抬起，并关闭打滑和地面扰动，隔离定位与转向响应；完整旋耕图才启用实际机具时序和反馈门控。

### 对照组

全部从距直线横向 0.25 米、同一航向出发，使用 60 米直线、同一控制器。

| 场景 | 相对理想基准的变化 |
|---|---|
| `ideal` | 无观测噪声、无传输延迟、无额外响应滞后；仍有加速度限制与现有 EMA |
| `position_noise` | 定位标准差 0.03 米 |
| `heading_noise` | 航向标准差 2° |
| `rtk_delay` | RTK 传输延迟 0.3 秒 |
| `response_lag` | 转向一阶响应时间 0.7 秒 |
| `combined` | 同时加入上述四项 |
| `combined_no_delay` | 保留组合场景其他项，只移除传输延迟 |

初次验证种子 42：

| 场景 | 中段真实横向 RMS | 中段真实横向峰峰值 |
|---|---:|---:|
| 理想基准 | 0.06 cm | 0.72 cm |
| 仅定位噪声 | 0.34 cm | 1.51 cm |
| 仅航向噪声 | 0.83 cm | 3.65 cm |
| 仅 RTK 延迟 | 0.04 cm | 0.35 cm |
| 仅响应滞后 | 0.41 cm | 3.43 cm |
| 组合场景 | 2.43 cm | 14.70 cm |
| 组合场景移除延迟 | 1.30 cm | 5.70 cm |

中段固定取真实前进位置 5–55 米，排除初始横向纠偏和终点制动。全程最大偏差、是否报告到达及真实终点误差另行输出，不能用中段 RMS 代替它们。三个额外种子 11、23、47 的组合 RMS 为 3.57–3.63 cm；相同种子移除延迟后为 1.40 cm 左右。

这说明这组参数下存在实际闭环摆动，并且多个因素会叠加；不能推导为“RTK 延迟单独必然画龙”，也不能把数值当作真实车辆的性能。图中的纵横坐标并非相同比例，横向误差被放大以便辨认。

### 航向来源的边界

传感器还提供 `heading_mode: position_delta`，用于研究两次定位差分得到行进方向的行为；静止或位移不足时 `heading_valid=false`。它需要外部运动/初始航向条件，当前直线闭环入口明确拒绝该模式，避免把“没有航向导致一直停车”误判成路径跟踪结果。

默认双天线模型的航向误差可单独设置。两者都不代表具体型号接收机的完整内部算法。接入实车日志前，先确认现场的航向来源、输出频率与时间戳含义。

## 3. 多进程仿真图

```bash
# 终端一，仓库根目录
python3 simulation/server.py --config simulation/config.yaml

# 终端二；需先安装运行时和图内节点的依赖
python3 -m edge.runtime.main configs/graphs/planning_simulation.yaml
```

保持实时模式。`--no-realtime` 只取消服务端节流，不会同步加速其他独立节点的墙钟和看门狗；不能把它视为多进程闭环的确定性加速器。

配置中的 `kinematics.dt`、`server.zmq_port`、`server.realtime` 会生效，显式命令行参数覆盖配置。`server.initial_pose` 可指定 `{x, y, yaw}`（米、弧度）；`field.boundary` 和 `field.fixed_holes` 可提供固定轮廓。

`sim_output.state_info.position` 已转换到与 `task_enu` 相同的坐标原点，原始仿真世界坐标另保存在 `world_position`。位置真值只接可视化评价，行走控制仍用 RTK。`sim_output.implement_state` 是机具物理反馈，接到机具状态机以确认到位。

仿真图的机具就绪条件是：逻辑作业状态、反馈接收年龄 ≤0.5 秒、悬挂达到作业高度的 95%、PTO 开启且 ≥480 rpm。反馈缺失、过期或未到位都保持等待。其他运行图默认不启用这个可选确认，需有相应反馈来源才开启。

## 4. 覆盖评价的口径

[evaluation.py](../simulation/evaluation.py) 可离线调用，也被在线轨迹可视化和规划结果绘图工具复用：

```python
from simulation.evaluation import evaluate_coverage

metrics = evaluate_coverage(
    samples,                 # x/y/theta，及真实 hitch_height、pto_on
    field_boundary,
    implement_width_m=1.2,
    field_holes=holes,
    implement_offset_m=-1.0,  # 相对位姿原点，负值代表后方
)
```

矩形机具随位置和朝向扫掠，默认按 0.25 米、2°细分，结果是几何近似。只有实际落下且 PTO 开启才计算作业。离线评价规划意图时可显式提供 `working`，此时得到的是预计覆盖，不能称为实际覆盖。

- **唯一覆盖**：至少耕过一次的地块有效面积。
- **遗漏**：扣除孔洞后的地块中尚未覆盖的面积。
- **重复面积**：地面离开机具后又进入机具的唯一面积；连续帧重叠和原地停留不算新的耕作遍数。
- **重复遍数面积**：重复区域按再次进入次数累计，与重复面积分开。
- **田外面积**：扫掠在地块有效区域之外的面积，包括进入孔洞。

重复面积仅是对比指标，不被一律当作失败。连续旋耕允许用更大半径和较多重叠换取平顺转弯，应同时观察遗漏、田外扫掠、曲率、抬刀次数及真实跟踪误差。

## 5. 验证与后续工作

2026-09-07 验证：`tests/unit` 与 `tests/integration` 共 **368 项通过**。另实际启动仿真服务与运行图 10 个独立节点，持续 30.2 秒；RTK、ENU、行走指令、机具实态反馈与 Web 统计均有更新，退出时无异常。

这次多进程短测也暴露了尚未解决的作业质量问题：入口对接偏差最大约 2.7 米，30 秒末仍约 1.16 米，且入口落刀产生田外扫掠。评价现在能把这些问题如实显示；后续要继续改善规划入口与跟踪，不能把链路运行成功当作整场作业验收。

```bash
python3 -m pytest tests/unit/test_simulation_*.py -q
python3 -m pytest tests/unit tests/integration -q
```

回归覆盖零速度停车、角度跨界、采样重放、超时重连、停止重试、不同 ENU 原点、机具实态确认、终点作业连续性及覆盖去重。历史 `simulation/tests` 中部分脚本会处理固定 5555 端口，本轮不依赖这些脚本充当验收入口。

下一步应收集同一时段的原始 RTK、航向来源、滤波位姿、目标点、转向指令、速度和机具状态，先核对频率、延迟及车辆转向响应，再做参数对照。尚未加入真实日志回放导入器，也没有把合成实验当成实车标定。

规划器方面，这轮保留已有覆盖规划器并统一评价口径。连续轮廓/螺旋连接、大半径跳行连接等候选，可在同一地块和机具尺寸下比较；外部规划库尚未接入。先看实际扫掠和可跟踪性，再决定要引入哪一个，避免只凭路径图看起来平滑就切换。
