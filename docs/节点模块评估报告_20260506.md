# NodeFlow 节点模块评估报告

> **评估日期**: 2026-05-06
> **评估范围**: 运行时框架、节点库 (node-hub / node-back)、SDK、仿真器、云平台、WebEditor、GUI、CLI
> **评分标准**: 每维度 1-5 分 (5=优秀, 4=良好, 3=合格, 2=不足, 1=严重缺失)，加权总分为百分制

---

## 评分维度说明

| 维度 | 权重 | 说明 |
|------|:----:|------|
| **代码完整性** | 30% | 功能实现是否完整，是否存在未完成的骨架代码 |
| **错误处理** | 25% | try/except 覆盖、边界校验、容错恢复、异常传播 |

### 2.2 节点评语

#### A+ (90+)

**tillage_controller** — 全仓库**质量标杆**。5态FSM + 转场白名单 + PTO互锁 + 紧急停止 + 区域自动检测。26个测试用例覆盖全部状态转换和边界条件，530行单元测试。L3 (run.py 数据I/O) / L4 (atom.py 纯算法) 分离典范。

**trajectory_viz** — **测试文件最多**的节点 (5个节点内测试 + 1个集成测试)。全栈实现 (web 实时可视化 + 轨迹度量计算 + 横向误差计算)。Web server 与算法逻辑分离清晰。

#### A (80-89)

**coord_transform** — 网关模式动态参考点获取 + WGS84→ENU 转换 + task_enu 去重转发。`atom.py` 仅 46 行纯函数，L3/L4 分离最极致的范例。无参设计 (所有坐标由端口动态注入)。

**sim_output** — 544行传感器聚合节点，20+ 可配置参数，ZMQ 断线重连 + 5次重试机制 + 场地数据保障。唯一不足：无独立单元测试。

**rtk_driver** — 量产级硬件驱动。双模 (串口/网络) + NMEA 解析 + 双天线定向 + 天线偏移补偿。5次重连 + 连接健康监测。18 个参数涵盖全部硬件配置场景。

**parcel_planner** — 独立坐标转换 (不依赖 coord_transform) + 边界验证 (NaN/Inf/类型/点数) + 文件去重。错误计数抑制机制避免日志洪水。

**global_coverage** — 往复式全局覆盖算法 + 路径文件保存 + 去重。依赖独立 `utils/` 模块降低了自包含性，但有专项测试 `test_global_coverage_standalone.py`。

#### B+ (70-79)

**arc_tracker** — `atom.py` 441行独立 Bezier 数学库 (求值/切线/曲率/弧长/角点圆化)，可直接独立发布。8 个参数覆盖巡航速度/预瞄动态/原地转向阈值/减速曲线。**零测试**是其唯一严重短板。

**trajectory_loader** — CSV/JSON 双格式加载 + 自动最新文件检测 + WGS84→ENU 转换 + waypoint→Bezier 角点圆化。659行，同样**零测试**。

**pwm_driver** — `atom.py` 318行纯算法 (差速运动学 + PWM映射 + 死区处理) + `run.py` 389行 sysfs 硬件控制。20 个参数含校准/安全/调试。**零测试**。

**waypoint_selector** — `atom.py` 479行，项目中**最复杂的算法**：视窗矩形算法 + 自动扩展启发式 + 连续消耗 + 区域跟踪。11 个参数。**零测试**——对如此复杂的逻辑应优先补充。

**sim_input** — 275行精简控制接口。看门狗超时 + 延迟连接初始化 + 退出时发送零指令的安全特性。无独立测试但被 E2E 覆盖。

**position_recorder** — Web UI + 手动/自动录制 + CSV/JSON 双格式 + 数据校验 (坐标范围/类型)。设计功能完整。

#### B (60-69)

**track_controller** — P控制器 + 原地转向逻辑 + 减速。189行精简实现，算法正确但**缺少单元测试**验证控制律。

**web_teleop** — 纯 stdlib HTTP 服务器 + 多线程 + JSON API + 直通模式 + 超时安全。**零测试**且依赖 `static/index.html` (未确认存在)。

**logger** — 10通道通用录制/回放 + pickle 序列化 + 倍速控制 + 循环回放。使用 pickle 在不可信数据场景下存在安全隐患。

**idle_detector** — 滑动窗口 Haversine 距离算法 + 消抖机制 + SharedBufferLite 写入。功能正确但整体较薄。

#### C+ (50-59)

**rtk_filter** — EMA 滤波 + 角度 wrap-aware + 可选 IMU 融合。`run.py` 含有大量注释掉的 schema 不匹配说明，说明与其他节点集成未对齐。

#### D (<40)

**shutdown_manager** — 76行全仓库最薄节点。仅将 `idle_event` 转发到 SharedBufferLite 并消抖，无 `atom.py`，无算法逻辑。**建议合并到 idle_detector**。

#### N/A

**network_input** — 仅有 `requirements.txt`，无 `node.yaml`、无 `run.py`，在 `node-hub` 中但实际未实现。

**整体评语**:

node-back 节点整体质量**明显低于** node-hub，体现为：
- **全无 L3/L4 分离** —— 所有节点均为早期单体架构
- **节点冗余严重** —— `pwm_controller` → `pwm_driver`、`rtk` → `rtk_driver`、`rmc_parser` → `rtk_driver`、`controller`/`velocity_controller` → `track_controller`/`arc_tracker` 均有功能对应的 node-hub 升级版
- **坐标系统落后** —— 使用原始 GPS 坐标计算，而 node-hub 已统一迁移到 ENU 局部笛卡尔系
- **仅 `velocity_controller` 有测试覆盖** (集成测试中间接覆盖)

**建议**: node-back 作为历史参考保留，新开发全部在 node-hub 进行。`farm_coverage_viz` 是唯一仍有独立价值的备线节点 (numpy/matplotlib 可视化)，但可考虑迁移到 node-hub 并添加 ENU 坐标支持。
