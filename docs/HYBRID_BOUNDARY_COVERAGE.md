# 主体大回转与沿边补作业

大部分田面继续用隔行大回转完成。主体作业结束后，根据还没扫到的区域，沿田边补几条直线；补边之间允许停车、抬机具和原地转向。重复经过已经耕过的地方是允许的。

选择 `wide_turn_boundary` 即可使用这套组合。原来的 `wide_turn` 仍可单独运行，用作对照。

## 补哪些边、补多少

规划器保留完整的主体路线，再从每条田边向内逐层布置候选直线。每次选择能覆盖最多剩余面积的一条，重新计算遗漏，直到达到目标、没有足够增益，或者候选层数用完。

这意味着补边不一定是完整地绕田一圈：长边已经覆盖得很好时，可以只补两端地头。转场仍是一段真实路径，会计入路程，抬起机具时经过的地面不会计为耕作。

补边按矩形机具实际能扫到的范围裁切端点，能收到边角；不会用圆形笔刷把没有耕到的角落涂成已覆盖。作业范围仍是扣除边界退让后的区域，不通过吃掉退让带提高数字。

首版沿用主体规划器的地块范围：单块凸形地，无孔洞。机具采用居中、零纵向偏置的简化模型，补边几何使用 0.2 米前后长度。不同机具的位置和尺寸需要与后续模型一起对应。

## 怎样接续两段

每段按既定顺序执行：

1. 沿当前段走到末端，停车。
2. 关闭动力输出、提升机具，等待抬起反馈。
3. 对准下一段方向。
4. 若下一段要作业，则落下机具并等待作业就绪，再前进；转场段保持抬起。

为此，组合计划给出明确的执行段。前瞻点不会越过当前段尾提前带着车辆转向，也不会因为补边与旧路线重合而跳过尚未执行的段。只有最后一段完成才报告整条路线结束。

补边期间的提升是计划动作，不再用“全程提升次数必须为零”判断成功。主体阶段仍检查是否发生了意外停刀，原地转向则检查机具是否已经实际抬起。

## 参数与复现

全局规划节点参数：

```yaml
planning_strategy: wide_turn_boundary
boundary_target_coverage_ratio: 0.98
boundary_max_layers: 16
path_point_spacing: 0.25
work_speed_limit_mps: 0.8
turn_speed_limit_mps: 0.5
```

`boundary_target_coverage_ratio` 是退让后作业区的**规划覆盖目标**。调高它会继续选取有增益的补边段；达不到时会保留实际覆盖率、剩余面积与停止原因。它不会被当成实测覆盖率。

沿用机具反馈连好的 `planning_simulation` 图。组合段执行会等待抬起和落下的就绪状态，不能仅接通行走输出而遗漏机具状态输入。

在仓库根目录运行规划对照：

```bash
python -m simulation.hybrid_comparison --output /tmp/nodeflow-hybrid-comparison
```

运行完整闭环：

```bash
python -m simulation.coverage_experiment \
  --strategy wide_turn_boundary --width 40 --length 70 --radius 4 \
  --coverage-target 0.98 --duration 7500 \
  --output /tmp/nodeflow-hybrid-tracking
```

也可以给同一命令增加 `--prepare-runtime`，生成相互匹配的服务与运行图配置，启动方式见 [连续旋耕规划器](CONTINUOUS_TILLAGE_PLANNERS.md)。演示仍从主体首段对齐出发。

## 同一地块的规划对照

2026-09-07，地块 40×70 米、四周退让 0.3 米、幅宽 1.2 米、重叠参数 10%、主体最小半径 4 米、曲率变化率上限 0.08。两种路线用同一矩形扫掠评价。

| 项目 | 主体大回转 | 加沿边补作业 |
| --- | ---: | ---: |
| 退让后作业区覆盖率 | 93.98% | 98.19% |
| 整块田的覆盖率 | 91.78% | 95.89% |
| 作业区遗漏 | 164.59 平方米 | 49.45 平方米 |
| 总路径长 | 2593.50 米 | 3012.04 米 |

选中了两层中的 4 条直线，安排 4 次抬机具转场。新增路程 418.54 米，其中补作业 156.8 米、转场 261.74 米。没有扫出田界。

两个阶段共享端点；评价时分别采用各段的朝向，避免把“停车后抬机具转正”的过程算成入土扫掠。上表仍是规划结果，实际跟踪、停刀时机和机具响应由闭环单独评价。

## 已完成的闭环结果

同一条组合路线已从头走到末尾，模拟耗时 6185.3 秒，约 103 分钟。下表来自同一次运行中主体结束和补边结束的真实位置、朝向与机具反馈。

| 实际覆盖 | 主体结束 | 补边结束 |
| --- | ---: | ---: |
| 整块田 | 90.37% | 95.18% |
| 退让后作业区 | 92.54% | 97.46% |
| 作业区仍未覆盖 | 204.07 平方米 | 69.46 平方米 |

补边实际增加覆盖 134.63 平方米。主体中途停刀 0 次，补边安排的 4 次停刀转场全部完成，机具入土且仍开动时的原地转向样本为 0；没有扫出田界。最终距路线终点 6.9 厘米，整条路线横向误差均方根 14.0 厘米，最大 41.2 厘米。

本次使用理想定位、无打滑、首段对齐的简化仿真。规划作业区目标 98% 对应实际 97.46%，因此目标与实测会分别保存。轨迹重放得到的覆盖、重复、路程和样本数与原始结果一致。

本轮单元、集成与全局规划测试 485 项通过。随后补充验证了两路路径消息先后到达时，完整作业计划不会被同版本的简化路径挡掉；对应执行与消息回归 8 项通过。

实际启动 10 个独立节点后，25 米短 U 形路线在 81.18 秒走完。1883 个前瞻点样本均保留执行段信息，102 个转正命令样本全部出现在实态机具已抬起、动力输出关闭之后。终点误差 6.6 厘米，没有错误日志，各进程正常退出。这项检查消息传递与动作接续；整田覆盖由上述完整路线闭环验证。

## 提高目标后的选段变化

同一地块把规划目标从 98% 提高到 99.5%，会从两层 4 条补边增加到四层 9 条，规划器内部估计的作业区剩余面积从 49.76 平方米降到 13.05 平方米。

99.5% 目标也完成了整条闭环：总路径 3470.03 米，模拟耗时 7255.2 秒，约 121 分钟。9 次补边转场全部完成，主体中途停刀和入土原地转向样本仍均为 0。

| 实际结果 | 主体结束 | 4 条补边，目标 98% | 9 条补边，目标 99.5% |
| --- | ---: | ---: | ---: |
| 退让后作业区覆盖率 | 92.54% | 97.46% | 99.06% |
| 整田覆盖率 | 90.37% | 95.18% | 96.74% |
| 作业区仍未覆盖 | 204.07 平方米 | 69.46 平方米 | 25.65 平方米 |

第二组补边新增实际覆盖 178.47 平方米，没有扫出田界。整田仍未覆盖的 91.25 平方米中，约 65.6 平方米来自预留退让带；其余是作业区内残余。两组轨迹重放与原始结果的全部核对项一致。

复跑高目标时，把完整闭环命令改为 `--coverage-target 0.995 --duration 9000`。

把目标设为精确 100% 时，则选到六层 15 条，还剩约 0.0024 平方米的微小区域；因为后续候选的新增面积不足，结果仍如实标记为未达目标。这组内部几何估计不替代上述统一矩形评价与实际闭环。

## 仍然保留的遗漏

达到 98% 后，规划器会停止增加补边段，因此图上仍有部分回转之间的缝隙。可以提高目标让它继续补，也可能最终遇到沿边直线够不到的残余形状。后一种情况会明确报告未达目标，后续再增加局部补耕方法。

这套组合先解决“主体平顺作业，少量边角允许抬刀处理”。它没有改变主路径的转弯半径，也没有把原始 NEPath 急转候选直接送进车辆。
