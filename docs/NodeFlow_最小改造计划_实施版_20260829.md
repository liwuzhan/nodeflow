## 1. 设计原则（实施时的裁决标尺）

| # | 原则 | 含义 |
|---|---|---|
| P1 | **责任跟幸存者走** | 任何责任必须交给在对应故障发生时仍活着的实体。节点死→框架办后事；框架死→模型办后事（模型在框架之外） |
| P2 | **节点的本分是"病了就大声死"** | 节点最清楚自己是否卡死，其职责是留下高质量遗言并退出（`sdk.die`）；复活归框架。pwm_driver `command_timeout` 为原型 |
| P3 | **框架 = 协议** | node.yaml 是 IDL，buffer 命名是寻址，latest-value+seq 是语义。模型的主接口是稳定的小工具（CLI/status）；裸读 mmap 仅作逃生通道 |
| P4 | **模型在环 vs 无人值守的分界** | 框架自主持有安全策略（租约、fail-closed 联动）的前置条件是**没有任何智能在环**（见 §4 触发条件） |
| P5 | **证据按衰减速率分类** | 证词随死即逝；遗言不可再生；现场无时间戳则无证明力；档案决定物证意义。**长久保存的是验尸报告，不是现场** |
| P6 | **三问测试**（职责归属判定） | ① 幸存者测试：故障发生时谁还活着？② 信息位置测试：该事实是否需要节点配合才能获得？③ 重复实现测试：若每个节点各写一遍，是否逐字相同？——框架负责**事实与后事**（幸存者测试失败项：死亡记录、复活与重试预算、run_id/incarnation 分配、启动排序/回滚/readiness 门控、跨节点聚合视图、清场与保留）；SDK 负责**重复实现测试逐字相同项**（心跳、父进程看门狗、结构化清理、参数解析、write_ts 盖戳、InputPort 状态机、输入看门狗机制、`sdk.die`）；节点负责**信息位置测试项**（"我病了"的判定、安全态的内容、业务 readiness 声明、设备时间透传纪律）。**框架永不解释 payload 的业务含义；节点永不复活自己、永不动全局状态** |

监督格（本计划补齐第三条边的接口）：

```
框架 ──(NodeMonitor 拉起+验尸)──→ 节点        已有/本计划加固
节点 ──(SDK 父进程检测)──→ 框架              已有
模型 ──(status / 死亡记录 / 探针)──→ 框架     本计划补齐
```

### 2.2 交叉评审新增发现（N-1～N-5）

| # | 发现 | 证据 | 设计影响 |
|---|---|---|---|
| N-1 | 单节点重启**复用**旧 buffer 且 seq 连续递增——重启在数据面完全不可见（seq 回跳/ts 倒退/inode 变化三个重同步触发器均不触发） | `port.py:53-57`（`create = not exists`） | 世代归属改由** incarnation **承担（§3 W2-2），不依赖数据面触发器 |

| N-3 | `get_sequence()` 为 seek+read 两次 syscall，非纯 mmap 读 | `shared_buffer_lite.py:158-160` | 热路径成本基线事实 |
| N-4 | 框架发现死亡最短延迟 ≈1.1s（监控周期 1.0s + communicate 0.1s）；20Hz 上游此时已覆写约 20 代 | `node_monitor.py:82,114,134` | 死后输入现场设计上不可恢复 → will/witness 分层（W2-4） |
| N-5 | health payload 的 inputs 仅为布尔连接态，无消费位置/年龄/世代 | `nodeflow_sdk.py:311-335` | W3-6 health v2 的直接修改点 |

## 3. 改造清单

### 波次 W1：无协议变更的修复（先行，约 200 行）

**W1-1 监控线程异常保护**（F-1）：`_monitor_loop` 循环体包 `try/except Exception: logger.exception; continue`。~10 行 + 注入异常测试。验收：连续注入异常下崩溃检测不中断。

**W1-2 重启失败进入重试调度**（F-2）：`_execute_restart` 失败/返回 None → `record_failure()` → `can_retry()` 则按退避重新入 `_pending_restarts`；重启尝试与节点崩溃共享 `max_retries` 预算。~15 行 + 测试。验收：回调连续失败 N 次后进入 give-up，非首败即弃。

**W1-3 CLI 后台启动改状态轮询**（F-3）：`sleep(2)` → 0.25s 轮询 `is_runtime_running()`，上限 10s，超时报错并提示日志路径。~15 行。

**W1-4 工程一致性收口**（F-9）：CI 触发分支加 `master` 与 `refactor/consolidate-post-ai-review`；`python_requires` 与 README 统一 3.12+；修 README ZMQ 残留与旧项目树；修 `startup_coordinator.py` docstring/日志；CI 增 `pytest tests/unit --collect-only` 门槛。~40 行（多为文档）。

**W1-5 `nodeflow status --json` 聚合命令**：聚合 run 信息（PID JSON + 图配置）、每节点状态（monitor + health 新鲜度）、每输出端口 seq/写入情况、按边推导的输入连通性、最近死亡记录摘要。daemon 模式经 `runtime.control` 查活体；非 daemon 回退读文件工件。~150-200 行（`tools/cli/commands/status_cmd.py`）。验收：单命令回答"哪些节点在跑、哪些输入断流、数据多旧、最近谁死过"。

### 波次 W2：协议 v2——时间与身份（约 400–500 行，一次协调升级）

**W2-1 Buffer header v2：写入时刻 + 版本防护**（F-6，含 R2）
- 布局：`[seq:4][length:4][write_ts_ns:8]`，`HEADER_SIZE 8→16`；`write_ts_ns` = `CLOCK_MONOTONIC`（Linux/macOS 系统级 boot 基准，同机跨进程可比）。
- 写序：`length=0 → payload → ts → seq → length`；读端一致性检查 8 字节→16 字节。
- SDK：`InputPort.last_write_age_ms()`；`recv_latest()` 签名不变。
- **版本防护（实施注记：采用 env 握手而非 header 首字节——首字节与 seq 语义冲突）**：launcher 经 `env_builder` 注入 `NODEFLOW_IPC_VERSION=2`（与 incarnation 同路径，各一行）；SDK 初始化时断言自身支持版本，不符则走 `sdk.die` 大声失败——杜绝"旧读者把 ts 当 payload 静默解析成空数据"的混读窗口（该窗口因 `--no-clean-buffers` 与 run 目录保留而真实存在）。同步更新 `test_shared_buffer_lite.py`、`test_port.py` 布局断言。
- ~70 行 + 测试。验收：任一端口写入年龄可查、误差 <5ms；版本不符进程大声退出而非静默空读。

**W2-2 run_id + incarnation**（F-6 档案层，含 D2）
- `start_dataflow` 生成 UUID `run_id`；PID 文件升级 JSON `{pid, run_id, started_at, graph_id, ipc_version}`（现两行文本，`main.py:809-816`）；`NODEFLOW_RUN_ID` 注入节点并进结构化日志前缀；资源路径改 `/tmp/nodeflow/<run_id>/buffers`（`constants.py` 动态化，CLI 经 PID 文件定位当前 run 目录）。
- **incarnation**：NodeMonitor/launcher 维护每节点计数（初值 1，重拉 +1），经 `NODEFLOW_INCARNATION` 注入（重启回调走 `launcher.launch` 每次重建 env，`main.py:402-417`，注入是一行）；与 RetryTracker 同生命周期，新 run 随 run_id 重置；SDK `report_health` 增加 `incarnation` 字段（节点零改动）。**世代归因走控制面，不进数据面 header**（W2-1 维持 16 字节）。
- ~95 行。验收：连续两轮 run 工件可按 run_id 区分；重启节点 health incarnation 递增且与死亡记录引用一致。
- **实施注记（容量）**：run 目录 × 保留 5 份 ≈ 百余 MB 级（每 run ~25-40 个 1MB buffer）。目标机若 /tmp 为 tmpfs 需注意内存占用；提供 `NODEFLOW_RUNTIME_ROOT` 环境变量允许把 buffer 根指到磁盘路径（开发机默认 /tmp 不变）。

**W2-3 InputPort 自愈与重同步**（F-5，R1 修订后语义）
- 状态机 `DISCONNECTED → CONNECTED`；`recv_latest()` 发现 buffer 为 None 时按退避（0.2s 起、上限 2s）重试打开。
- **重同步定位为安全网而非主路径**（N-1：默认复用型重启在数据面无痕迹，不触发重同步——这是设计选择而非缺陷，世代由 incarnation 承担）。触发条件保留：seq 大幅回跳 / ts 倒退 / **buffer 文件 inode 或尺寸变化**（服务于 W2-4 的改名留证重建路径与外部删除场景）→ 重开 mmap、`last_sequence` 重置、内部 `generation += 1`、INFO 日志。
- `get_stats()` 暴露 `{state, source_write_age_ms, generation}`。
- ~120 行 + 测试（含"生产者中途重建 buffer""生产者复用重启（不应触发重同步，只应看到 incarnation 变化）"两个用例）。验收：运行中重启上游，下游 ≤2 轮询周期恢复；损坏重建路径下游同样恢复。

**W2-4 死亡记录（核心交付物）**（F-6/F-7，schema 按 D3 修订）

```json
{
  "ts_wall": "...", "run_id": "...", "node_id": "rtk_sensor",
  "package": "sensing/rtk_driver", "incarnation": 3, "retry_count": 2,
  "exit_code": 1, "signal": null,
  "stderr_tail": "…≤500 字…",
  "will": {
    "health_age_ms_at_crash_detect": 1200,
    "inputs": { "serial_raw": {"last_seq_seen": 1204, "source_write_age_ms": 41000} }
  },
  "witness": {
    "output_ages_ms": {"rtk_fix": 41200},
    "input_ages_ms_note": "检测时刻上游活性，非节点死前所见",
    "input_ages_ms": {"serial_raw": 42000}
  },
  "quarantined_buffers": []
}
```

- `will` = 冻结 health 的摘录（节点生前证词，"饿死还是卡死"的**主证据**）；`witness` = 框架目击者账户（**旁证**）。两者互相印证：遗嘱说输入陈旧 41s 且检测时仍陈旧 → 饿死成立；遗嘱说输入新鲜且检测时也新鲜 → 自己卡死成立。**死后输入 buffer 已被上游覆写约 20 代（N-4），检测时刻年龄只作旁证，语义如实标注**。
- 写入者：NodeMonitor（幸存目击者）在 `_handle_node_crash` 追加 JSONL。
- **存储位置（R4 + 实施注记）**：默认解析链 `NODEFLOW_INCIDENT_DIR` → `~/.local/state/nodeflow/incidents`（XDG_STATE_HOME）→ `/var/lib/nodeflow/incidents`（仅当可写；注意 /var/lib 通常需 root，勿作唯一默认）。**不放 /tmp**——农机每日断电，故障上报必须活过断电。开发机可 `NODEFLOW_INCIDENT_DIR=<repo>/var/incidents`。
- 保留：滚动最近 1000 条或 30 天。
- ~100 行 + 测试。验收：强杀任一节点 → 记录完整落盘、will 与 witness 互相印证；断电重启后记录仍在；`status --json` 引用最近记录。

**W2-5 启动等待改 readiness 驱动**（F-4）
- `node.yaml` 可选 `readiness: heartbeat | first_output`（默认 heartbeat）；`_wait_for_layer` 每 0.1s 轮询：heartbeat = `{node_id}.health` 存在且新鲜；first_output = 全部输出 buffer `seq>0`；进程退出检查保留。`startup_timeout` 语义改为 readiness 上限（默认 10s），**超时告警放行**（与现状宽容度一致）。层间延迟 1s→0.1s（ZMQ 已移除）。
- ~80 行 + 测试。验收：11 节点真实 RTK 图启动时间实测对比记录。

### 波次 W3：打磨与约定（约 200 行，可拆散）

**W3-1 设备时间透传修正**：`rtk_filter` 不再以墙钟覆盖上游设备时间（`atom.py:59`），缺失时回退并标记 `timestamp_source: "local"|"device"`。~10 行。

**W3-2 现场保留（按 D2 §4.4 修订）**：run 作用域目录落地后跨 run 污染结构性消失；`_clean_buffers` 退役为兼容 no-op（新 run 天然空目录）。保留最近 5 个 run 目录，超限剪除前先对含死亡记录的 run 快照小端口最后 payload（单端口 >256KB 跳过）入 incidents 目录。~50 行。

**W3-3 节点输入看门狗约定**：manifest 可选 `input_watchdog: {<port>: <timeout_s>}`；SDK 超时调用节点 `on_input_lost`（**默认动作：`sdk.die`**，符合 P2；安全值输出留给节点自定义回调）。pwm_driver 迁移为首个用户。opt-in。~60 行 + pwm 适配。

**W3-4 stdout 日志降级**：1GB×30 → 64MB×3/端口（F-10）。2 行。

**W3-5 `sdk.die(reason, code=1)`（D1 新增）**：统一"大声死"——结构化 stderr 遗言（node_id、原因、关键端口年龄）→ flush → `os._exit(code)`（任意线程可调用；`sys.exit` 在非主线程仅终止线程、心跳线程假存活的坑由此杜绝）。现状 8 处手写 `traceback + sys.exit`（如 `pwm_controller/run.py:162`、`global_coverage/run.py:338`）逐步迁移。~15 行。

**W3-6 health payload v2（D3）**：`inputs` 由布尔升级 `{connected, last_seq_seen, source_write_age_ms}`（`last_seq_seen` 取 `InputPort.last_sequence`，`port.py:159` 现成；write_age 依赖 W2-1）；加 `incarnation`（依赖 W2-2）。`health_cmd` 同步适配，旧字段缺失降级显示。64KB 容量无虞。~40 行。

### 死亡时的 buffer 池策略（D2，实施时遵循）

- **默认复用**（现状 `create = not exists` 保持）：latest-value 全量快照语义下跨世代拼接无害；世代归因由 incarnation + health 承担。
- **例外：改名留证重建**——仅当 SDK 打开旧 buffer 发现 ① 打开/mmap 失败；② header 非法（length 越界等撕裂痕迹）；③ 文件尺寸与配置不符（顺手修 N-2）。处置：旧文件改名 `<name>.dead.<incarnation>.buf` 留证（不删除），新建同名池，下游经 W2-3 inode 安全网恢复；死亡记录引用被隔离文件名。
- **禁止级联**：单写者模型下节点重启只影响自己的输出池；对上下游做同样操作不存在必要，强行级联等于把单点故障放大成全图重连风暴。

## 4. 明确不做（触发条件登记，防范围回涨）

| 机制 | 触发条件（满足才立项） |
|---|---|
| Capability Registry / 能力租约 / 多提供者切换 | 出现第二定位源或第二执行源需**在线**切换 |
| 边侧 Desired-State Reconciler / 热重配 | 出现作业中不可整图重启的改图需求 |
| 类型化控制事件总线 | 出现多消费者控制面（云端+MCP+安全策略同时监听生命周期） |
| 运行时不变量注册表 / effect 诊断树 | W1/W2 落地后 status 输出仍不足以支撑模型诊断 |

## 5. 验收标准

**可靠性**
1. 注入监控线程异常 → 线程存活，崩溃检测不中断（W1-1）；
2. 重启回调连续失败 → 退避重试至预算耗尽（W1-2）；
3. 运行中强杀上游 → 下游 ≤2 轮询周期恢复（W2-3）；
4. 强杀任一节点 → 死亡记录落盘、will 与 witness 互相印证（W2-4）；
5. 整机断电重启 → 死亡记录与快照仍在（W2-4/W3-2）；
6. 多轮 start/stop 循环后 fd/线程/buffer 文件数回基线（扩展 `test_multi_loop.py`）；
7. 重启节点 → health `incarnation` 递增，status 与死亡记录引用一致（W2-2）；
8. 构造损坏 buffer（垃圾 header/尺寸不符）→ 旧文件改名留证、新池建立、下游 ≤2 轮询周期恢复、死亡记录引用隔离文件名（D2）。

**事实可读**
9. `status --json` 单命令回答在跑节点/输入连通与年龄/最近死亡摘要（W1-5）；
10. 任一端口写入年龄可查、误差 <5ms（W2-1）；两轮 run 工件按 run_id 可区分（W2-2）；
11. 强杀节点 → `will.inputs` 含 `last_seq_seen` 与 `source_write_age_ms`（W3-6）；
12. 冻结 health 时间戳距检测时刻 ≤ 心跳间隔 + 检测周期（≤3s），死亡时刻可定位（W3-6）；
13. health v2 下旧版 CLI 不崩溃（缺字段降级显示）（W3-6）。

**性能**
14. 典型图启动时间实测对比：固定等待 → readiness 驱动，记录数值（W2-5）；
15. write_ts 增量成本：20Hz 小包基准对比，确认无显著回退；16 字节一致性检查在目标工控机确认（W2-1）。
