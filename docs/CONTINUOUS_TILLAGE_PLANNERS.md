# 连续旋耕的新规划器

主体大回转之后的地头、边角补作业已接入，见 [主体大回转与沿边补作业](HYBRID_BOUNDARY_COVERAGE.md)。补边允许抬起机具转场，并根据剩余面积决定继续扫哪些边。

本轮增加了一条可接入现有运行图的“大半径隔行回转”路线，以及一个用于比较的现成螺旋刀路生成器。目的都是减少紧急折返和中途抬机具，允许多走一些、重复耕一些。

## 大半径隔行回转

选择 `wide_turn` 后，车辆不会耕完一行就立即折回相邻行，而是跨过若干行，用较宽的回环接到另一行，再逐步补回中间的行。

回环使用现有的回旋线求解库。直线进入弯道时，转向程度从零逐渐增加，出弯时再逐渐回到零。规划器按实际曲线检查半径、转向变化速度和地头空间，然后确定行序。所有生成的行都要访问，连接段也保持落刀作业。

路径布置会优先使用地块长轴。半径越大，通常需要跨越更多行、留出更深的地头；地块太窄或太短时会给出无法安排的原因。首版支持可行的凸形单块地，遇到孔洞、凹形或分离区域会拒绝，保留现有轮廓规划器处理这类地块。

每条直线都走到，不等于整块田完全没有遗漏。转弯连接会扫过一部分地头，仍未覆盖的角落和地头区域会被明确统计、画出。较多的重叠本身不判为失败。

### 运行参数

全局规划节点：

```yaml
planning_strategy: wide_turn
path_point_spacing: 0.25
work_speed_limit_mps: 0.8
```

任务中的车辆配置，例如：

```yaml
implement_width_m: 1.2
overlap_ratio: 0.1
path_inset_m: 0.3
pivot_turn: false
work_min_turn_radius_m: 4.0
work_max_curvature_rate_1pm2: 0.08
```

半径单位是米。最后一项约束转弯程度随行进距离变化的速度，数值越小，通常需要更长、更宽的过渡。示例是仿真用参数，没有改动实车控制增益。

输出仍为现有作业计划，路径点、作业段、限速和机具指令格式保持兼容。新路线全部标为作业段；运行图仍会等到真实机具反馈就绪后再前进。

规划摘要另外记录行序、访问行数、转弯数量、最小实际半径、地头深度、预计覆盖和剩余面积。入口只帮助选择整条路径的方向，**不生成从任意田门驶入首段的接近路线**。摘要中的 `start_pose` 给出首段的位置和朝向，仿真演示据此初始化。

## 现成的费马螺旋候选

NEPath 已从固定上游提交实际编译并接通。它可以从边界和孔洞生成沿轮廓盘绕、连接的路线，适合继续借鉴打印和数控加工的布局思路。

实际小算例很能说明两类机械的差别：40×30 米矩形、1.2 米幅宽时，它的圆形缓冲覆盖估计超过 99%，但最紧处的抽样转弯半径只有约 0.15 米；中央有孔洞的算例约 0.11 米。这些连接对刀头可行，对要求数米半径的车辆还不合适。

因此当前把它作为原始几何候选，保留全部拐角和不合格位置，独立的路径也不会被直线强行拼起来。它没有加入在线策略列表。后续值得改的是换圈和中心连接，而不是把过小半径隐藏掉。

安装与直接调用见 [NEPath 可选安装说明](NEPATH_OPTIONAL.md)：

```bash
python3 tools/optional/install_nepath.py
```

该脚本关闭两个可选优化器。现有 `wide_turn` 只使用规划节点原有依赖，不需要安装 NEPath。

## 怎样比较路线

在仓库根目录安装相关依赖：

```bash
python3 -m pip install -r simulation/requirements.txt
python3 -m pip install -r edge/nodes/planning/global_coverage/requirements.txt
```

离线比较路径形状、扫掠和转弯：

```bash
python3 -m simulation.planner_comparison \
  --cases long_rectangle wide_rectangle \
  --output /tmp/nodeflow-planner-comparison
```

默认比较旧轮廓、新大回转和 NEPath 候选；未安装 NEPath 时会标注缺少依赖。每种路线分别输出完整路径、指标和图片，生成失败也会保留原因。

覆盖统一使用矩形机具扫掠，分别报告“退让后的作业区域”与“整块有效田地”的覆盖率。不能把两种分母混在一起。图上区分已覆盖、重复和遗漏；曲率图同时保留原始点间转角密度和固定距离取样结果，避免将折线密化造成的局部峰值误当成原曲线半径，又不隐藏接头急转。

固定距离取样仍是诊断值，窗口短于原曲线采样间距时也可能产生假峰；它不能替代解析曲线的半径验收。新规划器另外检查回旋线本身的曲率及其变化率。

### 已完成的同地块对照

2026-09-07，地块为 102×30 米，四周退让 1 米后，作业区域为 100×28 米。幅宽 1.2 米、重叠参数 10%、要求最小半径 4 米。下表来自统一矩形机具扫掠，尚未包含车辆跟踪误差。

| 路线 | 作业区域覆盖率 | 重复面积占作业区域 | 路线长度 | 作业转为转场次数 |
| --- | ---: | ---: | ---: | ---: |
| 现有轮廓螺旋 | 97.60% | 88.67% | 6507.76 米 | 6 |
| 大半径隔行回转 | 96.82% | 15.03% | 2719.65 米 | 0 |
| NEPath 原始候选 | 99.91% | 11.7% | 2587.50 米 | 0，但急转不满足车辆约束 |

这里的重复面积指“被覆盖至少两次的区域”，不是累计重复经过的面积。新路线的重点是连续作业与可转弯；较低重复和较短路程只是这组地块的结果，不把少重复作为硬约束。NEPath 的零转场也不表示可以直接执行。

### 带机具反馈的控制闭环

```bash
python3 -m simulation.coverage_experiment \
  --width 40 --length 70 --radius 4 --duration 6600 \
  --output /tmp/nodeflow-wide-turn-tracking
```

这个入口用新规划器生成路线，复用 RTK 滤波、路径进度、前瞻点、行走控制和机具状态机。仿真从第一作业段对齐出发，先落机具、等待实际反馈，再前进。它会输出真实轨迹、控制状态、实际覆盖和结束原因。达到时间上限或需要重新摆正车辆时，结果不会写成“完成”。

轨迹每 0.1 秒记录一次，覆盖每 0.5 秒及作业开关变化时取样，再按空间距离和朝向细分扫掠。直线实验中的定位噪声机制仍可用于该入口；默认这组整田验证采用无扰动观测，先隔离规划与控制的配合。

如果要启动实际独立进程和网页，先生成相互匹配的演示配置：

```bash
python3 -m simulation.coverage_experiment --prepare-runtime \
  --width 40 --length 70 --radius 4 --output /tmp/nodeflow-wide-turn-demo

# 终端一
python3 simulation/server.py --config /tmp/nodeflow-wide-turn-demo/server.yaml

# 终端二，需安装运行时及图内节点依赖
python3 -m edge.runtime.main /tmp/nodeflow-wide-turn-demo/graph.yaml
```

这组配置同样从首段对齐开始，用于比较规划器；田门进入、离开地块和多块地之间的转场需要单独安排。

### 已完成的整条路线验证

上述 40×70 米示例已运行至终点，包含 37 行、36 次回转。规划路径长 2593.50 米，解析最小半径 4.136 米；模拟时间 5202.5 秒，约 86.7 分钟。

| 检查 | 结果 |
| --- | ---: |
| 路线完成 | 是，终点距离 0.426 米 |
| 中途 PTO 关闭次数 | 0 |
| 真实横向误差 RMS / 最大绝对值 | 0.152 / 0.412 米 |
| 实际覆盖整块田 | 90.36% |
| 剩余面积 | 270.01 平方米 |
| 重复区域 | 447.07 平方米，15.97% |
| 扫出田界的并集面积 | 0 平方米 |

覆盖取自模拟真实位置和机具反馈，采用 1.2×0.2 米、零纵向偏置的矩形机具。车辆与机具仍是简化模型，默认定位无噪声、无打滑，从首段对齐出发。这里的 `completed` 表示走完规划路线，**不是 100% 覆盖**。图中弯道存在约四十厘米的跟踪内切，地头遗漏需要继续改善，不能只凭规划半径合格就认为实车跟踪问题已解决。

另外启动了实际的 10 个独立节点，检查新计划发布、机具反馈就绪和车辆开始作业：运行约 31 秒、移动 12.63 米，没有 ERROR/CRITICAL 日志，停止后正常清理。这项只验证启动与首段，整条转弯路线由上面的离线闭环验证。

本轮单元、集成及全局规划测试合计 454 项通过；运行进程时发现并修正了新日志调用与 SDK 的参数兼容问题，随后严格日志接口回归 5 项和独立进程验证通过。

## 本轮附带修正

- 规划结果广播期间读到的新任务会留下来进入下一次规划，避免读取后丢掉更新。
- 长路线的累计里程按计划缓存，不再每个控制周期从头计算；投影和距离计算本身保持一致。
- 机具状态机可使用仿真时钟，使离线加速实验中的下降、PTO 启动和提升按仿真时间推进。
- NEPath 始终只返回候选，运行入口拒绝将它误当作已检查的作业路线。

当前仍需继续改善地头剩余区域、孔洞周围的大半径连接，以及任意入口到首段的对接。新规划器提供了可运行、可对照的基础，后续可据真实遗漏图判断应补轮廓回环还是调整行序。
