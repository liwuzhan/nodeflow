## 概览与结论

- 架构定位清晰：以声明式 YAML 驱动的“节点化”框架，结合 SharedBuffer + ZeroMQ 的混合 IPC，兼顾最新值语义与实时通知，整体设计合理且面向边缘计算落地。
- 运行时（Runtime）工程化较成熟：启动编排、拓扑分层、节点日志与健康监控都有完整实现，具备稳定的关停与应急清理路径。
- SDK 与工具链完善：端口抽象、参数解析、CLI 诊断与健康检查、测试工具库齐全，便于节点开发与集成。

- 主要改进点在于：历史 IPC 模块与现行混合架构并存导致的路径与实现不一致、ZMQ 细节参数的健壮性、类型校验策略、日志滚动阈值、文件权限与清理策略等工程细节。

总体结论：架构正确、实现到位、测试充足，具备生产级可用性；建议在一致性与安全可维护性方面做有序收敛与优化。

## 详细问题与优先级

### Critical
- 未发现阻断性或高危问题（路径安全与启动超时已在最近版本修复）。

### Major
- IPC 路径与实现不一致（新旧并存）
  - 现象：`runtime/ipc/shared_buffer.py` 使用 `/tmp/nodeflow_buffers` 与 `.mem` 扩展；现行实现与文档约定为 `/tmp/nodeflow/buffers` 与 `.buf`。
  - 影响：认知成本升高、误用风险、工具链不统一；新旧混用可能导致读写不一致。
  - 建议：统一所有模块到 `runtime/utils/constants.py` 路径常量；明确弃用旧 IPC 模块并在文档标注；工具与 SDK 仅保留 SharedBufferLite + ZMQ 混合架构。
  - 参考：[shared_buffer.py:L38-L62](file:///Users/wuzhanli/Desktop/node/runtime/ipc/shared_buffer.py#L38-L62)、[constants.py:L1-L3](file:///Users/wuzhanli/Desktop/node/runtime/utils/constants.py#L1-L3)

- 日志滚动阈值过大（1GB x 30）
  - 现象：节点日志滚动器默认 30GB 上限。
  - 影响：边缘设备磁盘压力，日志清理窗口过长。
  - 建议：调整默认上限为 64MB-256MB x 7-10 份；将阈值纳入运行时配置或环境变量。
  - 参考：[node_launcher.py:L97-L114](file:///Users/wuzhanli/Desktop/node/runtime/orchestrator/node_launcher.py#L97-L114)

### Minor
- 类型不匹配仅警告
  - 建议：增加严格模式开关（例如环境变量或 CLI 选项），在 CI/生产场景下将类型不匹配视为错误。
  - 参考：[graph/validator.py:L91-L103](file:///Users/wuzhanli/Desktop/node/runtime/graph/validator.py#L91-L103)

- ZMQ 关停健壮性
  - 建议：PORT 层设置 `ZMQ_LINGER=0`，减少退出阻塞；InputPort 采用 Poller 改善轮询效率。
  - 参考：端口关闭路径：[port.py:L419-L437](file:///Users/wuzhanli/Desktop/node/sdk/port.py#L419-L437)

- 缓冲区权限与清理
  - 建议：创建 `.buf` 文件后设置 0600 权限；目录 0700；在应急清理与关停时校验并修复权限。

### Suggestion
- 将健康检查快照（buffer 序列增长、长度摘要）周期性写入运行时日志，便于远程诊断。
- 在工具链中增加“严模式”开关统一影响 GraphValidator 与 CLI 检查输出。
- 为 OutputPort 支持“结构化通知”（例如主题包含 port 名与简要类型），方便跨语言订阅者。
