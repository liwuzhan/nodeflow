# WaypointSelector 节点设计文档（简化版）

## 🎯 节点概述

**节点名称**：`waypoint_selector`  
**核心功能**：基于车辆当前位置和航向，从规划轨迹中选择下一个前瞻点  
**设计理念**：简单、专注、可配置的单一职责节点

---

## 📥 输入接口

### 1. **全局路径** (`global_path`)
- **类型**：`List[Tuple[float, float]]`
- **描述**：规划好的轨迹点序列，ENU坐标系
- **要求**：点顺序即为规划顺序，相邻点间有适当间距（建议0.5-2.0米）

### 2. **车辆姿态** (`vehicle_pose`)
- **类型**：包含 `(x, y, theta)` 的结构体
- **描述**：
  - `x, y`：ENU坐标系中的位置（米）
  - `theta`：航向角（弧度），数学坐标系（东=0，逆时针为正）
- **频率**：与控制周期同步（通常20-50Hz）

---

## 📤 输出接口

### **前瞻点** (`lookahead_point`)
- **类型**：`{"x": float, "y": float, "final": bool}`
- **描述**：
  - `x, y`：前瞻点坐标（ENU坐标系）
  - `final`：布尔值，表示是否到达终点
- **说明**：
  - 正常工作时 `final=false`
  - 所有轨迹点消费完毕时 `final=true`

---

## 🔧 核心算法

### **三类轨迹点定义**

1. **已消费点 (Consumed Points)**
   - 曾经是视野点且已退出视野
   - 不再参与任何计算
   - 永久性标记

2. **视野点 (In-view Points)**
   - 当前位于视野区域内的轨迹点
   - 必须是按规划顺序连续的点（不能跳过中间点）
   - 实时更新，随车辆运动变化

3. **未消费点 (Unconsumed Points)**
   - 尚未被视野覆盖过的轨迹点
   - 按规划顺序等待被消费

### **视野区域定义**

```
       车辆航向
           ↑
           │
        ┌──┴──┐
        │     │  视野区域
        │  ●  │←─ 距车辆 w 米
        │     │  的"视野带"
        └─────┘
          车辆
```

- **形状**：矩形区域（简化计算）
- **位置**：车辆正前方，距离车辆位置 `w` 米处
- **大小**：宽度为 `2×h`，高度为 `d` 的矩形
  - `h`：半宽参数（左右扩展）
  - `d`：深度参数（前后厚度）
- **方向**：与车辆航向方向一致

### **前瞻点选择规则**

1. **视野内有视野点时**
   ```
   轨迹： ●─●─●─●─●─●─●─●─●
          已消费│  视野点  │未消费
               ▼          ▼
              ● ● ● ● ●   ● ● ●
               ↑     ↑
           第一个  最后一个（输出为前瞻点）
   ```
   - 输出视野点中**按规划顺序最后一个点**

2. **视野内无视野点时**
   ```
   轨迹： ●─●─●─●─●─●─●─●─●
          已消费│ 未消费 │
               ▼       ▼
              ●        ● ● ● ●
                        ↑
                    自动成为前瞻点
   ```
   - 输出第一个未消费点作为前瞻点

3. **无未消费点时**
   - 输出最后一个轨迹点，并设置 `final=true`

### **状态转移逻辑**

```
初始化: 所有点均为未消费点

循环处理:
  1. 根据车辆位置和航向计算当前视野区域
  2. 从第一个未消费点开始检查:
      a. 如果点在视野内且与上一个视野点连续 → 标记为视野点
      b. 否则 → 停止检查（保持规则：不跳过点）
  3. 更新视野点集合:
      a. 新进入视野的点加入集合
      b. 退出视野的点移出并标记为已消费
  4. 根据规则选择前瞻点输出
```

## ⚙️ 可配置参数

### **视野参数**
```yaml
view_distance: 3.0      # w：视野中心距车辆距离（米）
view_width: 4.0         # 2h：视野矩形宽度（米）
view_depth: 1.0         # d：视野矩形深度（米）
```

### **性能参数**
```yaml
max_search_points: 100  # 每次最多检查的点数
min_point_spacing: 0.3  # 最小点间距（米），用于优化
```

### **调试参数**
```yaml
enable_visualization: false  # 是否输出调试信息
log_level: "INFO"            # 日志级别
```

## 📊 配置建议

### **低速覆盖场景**（速度 < 1.0 m/s）
```yaml
view_distance: 2.0  # 稍短的前瞻距离
view_width: 3.0     # 覆盖车辆作业宽度
view_depth: 0.5     # 较薄，确保精确跟踪
```

### **中速运输场景**（速度 1.0-2.0 m/s）
```yaml
view_distance: 4.0  # 较长前瞻距离
view_width: 2.0     # 较窄，关注正前方
view_depth: 1.0     # 中等厚度
```

### **高速场景**（速度 > 2.0 m/s）
```yaml
view_distance: 6.0  # 长前瞻距离
view_width: 1.5     # 窄视野，减少干扰
view_depth: 1.5     # 较厚，平滑过渡
```

## ⚠️ 边界情况处理

### **1. 车辆偏离路径**
- **现象**：视野内无轨迹点
- **处理**：输出第一个未消费点（即使不在视野内）
- **目的**：引导车辆回到路径

### **2. 路径点过于稀疏**
- **现象**：视野区域内可能没有点
- **预防**：规划时确保点间距 < view_distance
- **处理**：同上，输出第一个未消费点

### **3. 航向突变**
- **现象**：视野区域突然转向
- **处理**：视野点集合清空，重新计算
- **说明**：这是期望行为，防止使用旧视野点

### **4. 到达终点附近**
- **现象**：最后一个点被消费
- **处理**：输出终点并标记 `final=true`
- **后续**：由上游节点决定停止或新任务

## 📈 性能特性

### **计算复杂度**
- **最优情况**：O(k)，k=max_search_points
- **空间复杂度**：O(n)，n=轨迹点总数（仅存储消费状态）

### **实时性**
- 单次计算时间 < 1ms（1000个点以内）
- 适合50Hz控制频率

### **内存使用**
- 每个点：位置(16字节) + 状态(1字节)
- 1000点轨迹 ≈ 17KB

## 📝 设计决策说明

### **选择矩形视野而非扇形**
- **理由**：计算简单，判断快速
- `point_in_rectangle` 比 `point_in_sector` 更快
- 实际效果与扇形近似，但参数更直观

### **不跳过中间点**
- **理由**：保证路径覆盖完整性
- 尤其重要于覆盖任务（农业、清洁）
- 防止漏掉关键路径点

### **简化消费逻辑**
- **理由**：避免复杂覆盖判定
- "退出视野即消费" 规则简单明确
- 配合适当视野参数，可确保覆盖

### **单一输出模式**
- **理由**：接口稳定，易于理解
- 下游控制器无需适应多种模式
- 调试和测试更简单
