## 概述

### 什么是节点？

节点是 NodeFlow 框架中的基本计算单元，代表一个独立的进程。每个节点通过 Unix Domain Socket 与其他节点进行数据交互。

### 节点特性

- **独立进程**：每个节点作为单独的 Python 子进程运行
- **声明式配置**：通过 YAML 文件声明端口和参数
- **进程间通信**：基于 Unix Domain Socket 的 JSON 消息传输
- **非阻塞接收**：使用 `recv_latest()` 获取最新值（不排队）
- **参数化**：通过环境变量传递配置给节点进程

### 节点的三个角色

1. **源节点** (Source) - 仅有输出，无输入
2. **处理节点** (Processing) - 既有输入又有输出
3. **汇节点** (Sink) - 仅有输入，无输出

## 架构模式 (4层架构)

为了解决分布式系统开发中依赖链模糊、调试困难等问题，NodeFlow 推荐采用 **4层架构 (4-Layer Architecture)**。这种架构将系统分层，实现极致解耦。

### 核心分层定义

| 层级 | 名称 | 定义 | 职责 | 特征 |
| :--- | :--- | :--- | :--- | :--- |
| **L4** | **原子层 (Atoms)** | 最小粒度的业务逻辑单元 | 纯算法实现、数学计算 | **纯函数**、无副作用、无框架依赖 (禁止 import sdk/runtime) |
| **L3** | **分子层 (Molecules)** | 独立运行的进程节点 (Node) | 数据搬运、组装原子、状态管理 | **禁止横向依赖**、非阻塞 IO、只负责收发不负责计算 |
| **L2** | **协调层 (Coordinator)** | 控制流中心与数据总线 | 显式编排、状态公示 | YAML 配置、共享缓冲区、ZMQ 通知 |
| **L1** | **入口层 (Entry)** | 生命周期管理器 | 启动进程、监控健康 | `runtime/main.py` 等启动脚本 |

### 为什么使用4层架构？

1.  **AI 友好**：AI 编写 L4 层的纯算法代码准确率极高。
2.  **易于测试**：L4 层可进行 100% 覆盖的单元测试，无需启动运行时；L3 层只需 Mock 数据流。
3.  **调试变革**：从“追踪代码执行流”转变为“查表式调试”（检查 L2 层的数据板状态）。

## 节点结构

### 目录布局 (L3/L4 分离实践)

每个节点包（Node Package）内部应强制实施分层：

```
node-hub/
├── my_node/                    # 节点包目录
│   ├── atom.py                # [L4] 核心算法 (纯数学，无依赖)
│   ├── run.py                 # [L3] 节点逻辑 (只负责收发数据 + 调 atom)
│   ├── node.yaml              # 节点声明文件（必需）
│   ├── README.md              # 节点文档（推荐）
│   ├── requirements.txt        # 节点依赖（可选）
│   └── test/                  # 测试目录
│       ├── test_atom.py       # [L4测试] 针对 atom 的单元测试 (极快)
│       └── test_node.py       # [L3测试] 针对 run 的集成测试 (Mock SDK)
```

### 文件说明

| 文件 | 层级 | 必需 | 用途 |
|------|------|------|------|
| `node.yaml` | 接口 | ✅ | 声明节点的端口、参数、入口点 |
| `run.py` | L3 | ✅ | 节点的主要实现代码（数据搬运、胶水逻辑） |
| `atom.py` | L4 | ⭐ | 核心算法逻辑（纯函数，无 SDK 依赖） |
| `README.md` | 文档 | ⭐ | 节点的使用说明和参数文档 |
| `test/` | 测试 | ⭐ | 包含单元测试和集成测试 |

## node.yaml 规范

### 完整模板

```yaml
# 基本信息
name: node_name                    # 节点包名（必需，英文，唯一）
version: "1.0.0"                   # 版本号（推荐语义化版本）
description: "节点描述"             # 简短描述（必需）

# 启动入口
entrypoints:                       # 各平台的启动方式（必需）
  linux:
    kind: python                   # 运行环境（必需：python）
    cmd: ["python3", "run.py"]     # 启动命令（必需）
  darwin:
    kind: python
    cmd: ["python3", "run.py"]
  windows:
    kind: python
    cmd: ["python", "run.py"]

# 端口定义
ports:                             # 端口集合（必需）
  inputs:                          # 输入端口列表（可为空）
    - name: input_name
      type: json                   # 数据类型（json, any）
      description: "输入说明"

  outputs:                         # 输出端口列表（可为空）
    - name: output_name
      type: json
      description: "输出说明"

# 参数定义
params:                            # 参数字典（可为空）
  param_name:                      # 参数名
    type: string                   # 参数类型（string, number, bool）
    default: "default_value"       # 默认值（可选）
    required: false                # 是否必需（可选）
    description: "参数说明"
```

### 重要规则

#### ❌ 常见错误 - YAML 格式错误

```yaml
# ❌ 错误：params 不能是列表！
params:
  - name: param1
    type: string
  - name: param2
    type: number

# ✅ 正确：params 是字典
params:
  param1:
    type: string
  param2:
    type: number
```

#### ❌ 常见错误 - 端口格式错误

```yaml
# ❌ 错误：inputs/outputs 不能在顶级
inputs:
  - name: input1
outputs:
  - name: output1

# ✅ 正确：必须在 ports 内
ports:
  inputs:
    - name: input1
  outputs:
    - name: output1
```

#### ❌ 常见错误 - 缺少 entrypoints 的 kind 字段

```yaml
# ❌ 错误：缺少 kind
entrypoints:
  linux:
    cmd: ["python3", "run.py"]

# ✅ 正确：必须指定 kind
entrypoints:
  linux:
    kind: python
    cmd: ["python3", "run.py"]
```

## run.py 实现规范

### L3 "傻瓜式" 循环模式

`run.py` 应尽量保持简单，只负责数据收发和调用 `atom.py`。

```python
#!/usr/bin/env python3
"""
节点名称：<节点名>
功能描述：<说明>
"""

import time
import sys
from pathlib import Path

# 添加 SDK 路径
sys.path.insert(0, str(Path(__file__).parent.parent.parent))
# 添加当前目录以导入 atom
sys.path.insert(0, str(Path(__file__).parent))

from sdk.nodeflow_sdk import NodeFlowSDK
# 导入 L4 原子逻辑
import atom 

def main():
    """节点主函数"""
    # 初始化 SDK (context manager)
    with NodeFlowSDK(log_level="INFO") as sdk:
        sdk.logger.info(f"节点启动: {sdk.node_id}")

        # 1. 读取参数
        param1 = sdk.get_param('param1', 'default')

        # 2. 创建端口
        input_port = sdk.create_input_port('input_name')
        output_port = sdk.create_output_port('output_name')

        # 3. 主循环
        try:
            while True:
                # 3a. 接收输入（非阻塞，L3 职责）
                data = input_port.recv_latest()
                
                # 3b. 处理逻辑（调用 L4 原子）
                if data:
                    # 节点不负责思考，只负责传参
                    result = atom.compute_something(data, param1)
                    
                    # 3c. 发送输出（L3 职责）
                    output_port.send(result)
                
                # 3d. 休眠
                time.sleep(0.02)  # 50Hz

        except KeyboardInterrupt:
            sdk.logger.info("收到关闭信号")
        except Exception as e:
            sdk.logger.error(f"错误: {e}", exc_info=True)

if __name__ == '__main__':
    main()
```

### 关键实现细节

1.  **SDK 初始化**：必须使用 `with NodeFlowSDK(...) as sdk:` 上下文管理器。
2.  **参数读取**：使用 `sdk.get_param()`，不要直接读环境变量。
3.  **非阻塞接收**：使用 `recv_latest()`。不要使用 `time.sleep` 等待特定节点启动，应处理数据为 `None` 的情况。
4.  **禁止横向依赖**：`run.py` **不允许** `import node-hub/其它节点` 的任何代码。

## 数据传输协议

### 消息格式

所有数据通过 Unix Domain Socket 以 JSON 格式传输。

```
[4字节长度前缀][JSON消息体]
```

### 数据类型规范

#### JSON 类型（推荐）

```python
# GPS 数据示例
{
    "timestamp": 1703024780.123,
    "seq": 1,
    "latitude": 39.9042,
    "longitude": 116.4074
}
```

#### 字段约定

- **timestamp**: 浮点数，秒级时间戳（必需）
- **seq**: 整数，消息序号，从0递增（必需）
- **其他字段**: 根据数据类型定义

## 数据契约与Schema定义

从 NodeFlow 2.1 版本开始，我们推荐使用 **"Code as Single Source of Truth"** 的方式定义数据契约。

### 核心理念

*   **定义在代码中**：使用 Python 的 `pydantic` 库定义数据结构。
*   **零运行时开销**：默认情况下（`loose` 或 `off` 模式），运行时不执行校验，保证高性能。
*   **元数据暴露**：SDK 自动提取 Schema 并发布到 Metadata Buffer，供 CLI 工具离线体检。

### 如何定义 Schema

在 `run.py` 中：

```python
from pydantic import BaseModel, Field

# 1. 定义数据结构 (The Contract)
class GPSData(BaseModel):
    lat: float = Field(..., ge=-90, le=90, description="纬度")
    lon: float = Field(..., ge=-180, le=180, description="经度")
    alt: float = Field(default=0.0, description="海拔")
    status: int = Field(..., description="定位状态")
    timestamp: float

def main():
    with NodeFlowSDK(log_level="INFO") as sdk:
        # 2. 绑定 Schema 到端口
        # SDK 会自动发布此 Schema 到 Metadata
        gps_out = sdk.create_output_port("gps_fix", schema=GPSData)
        
        while True:
            # 3. 发送数据
            # 方式 A: 直接发送对象 (SDK 自动序列化)
            data_obj = GPSData(lat=39.9, lon=116.4, status=1, timestamp=time.time())
            gps_out.send(data_obj)
            
            # 方式 B: 发送字典 (SDK 仅在 Strict 模式下校验)
            # data_dict = {"lat": 39.9, "lon": 116.4, "status": 1, "timestamp": time.time()}
            # gps_out.send(data_dict)
```

### 校验模式

可以通过环境变量 `NODE_SCHEMA_VALIDATION` 控制校验行为：

*   **off** (默认): 不校验，最高性能。
*   **loose**: 校验失败打印 Warning，不阻断发送。
*   **strict**: 校验失败抛出异常，阻断发送。

### 验证工具

使用 CLI 工具进行离线体检（不影响运行）：

```bash
python3 tools/cli/core/cli.py health check <node_id>
```

## 端口系统

### 端口命名规范

- **输入端口**: `snake_case`，使用下划线分隔
- **输出端口**: `snake_case`，使用下划线分隔

### 端口连接规则

在 YAML 配置中定义端口连接：

```yaml
edges:
  - from: source_node.output_port
    to: target_node.input_port
```

**约束**:
- 一个输出端口可连接到多个输入端口（一对多）
- 一个输入端口只能连接到一个输出端口（多对一）
- 不能形成循环依赖

## 最佳实践

### 1. 状态驱动设计 (State-Driven Design)

NodeFlow 架构强烈推荐**将“事件”建模为“持续的状态”**，而非瞬时的脉冲消息。

*   **物理世界的本质**：在机器人与自动化领域，所谓的“事件”（如急停、支付成功）通常对应一个持续的物理状态或业务状态。
    *   *急停*：不是一个瞬间的信号，而是急停开关被拍下后，电路持续断开的**状态**。
    *   *支付成功*：不是一个通知，而是订单状态从 `PENDING` 变为 `PAID` 的**状态变更**。
*   **设计模式 - 状态锁存 (State Latching)**：
    *   **源节点**：应持续广播当前的最新的“真值”状态（如 `ESTOP: ACTIVE`），直到状态被物理复位或逻辑清除。
    *   **处理节点**：使用 `recv_latest()` 以自己的节奏轮询。只要源节点持续发送状态，下游就绝不会错过“急停”——即使丢了中间的 10 个包，第 11 个包依然会告诉它“现在是急停状态”。
    *   **优势**：天然容错（Anti-fragile）。无需复杂的 ACK/重传队列，利用高频状态刷新来覆盖网络抖动。

### 2. 架构与设计 (AI 友好)

- **L4/L3 分离**：将核心算法剥离到 `atom.py`，保持 `run.py` 简单。
- **显式状态**：节点应在输出中包含 `status` 字段（如 `WAITING`, `RUNNING`, `ERROR`），便于“查表式调试”。
- **切断横向依赖**：节点应假设自己是世界上唯一的进程，不依赖其他节点的启动顺序。

### 3. 特殊场景：内部队列
如果确实存在必须处理每一条历史记录的场景（如统计日志、审计追踪），**不要依赖通信层队列**，而应在节点内部实现缓冲逻辑，或使用专门的时序数据库/日志服务。通信层应保持轻量和即时。

### 4. 测试策略

- **L4 测试**：针对 `atom.py` 编写单元测试，覆盖所有算法分支（极快，无依赖）。
- **L3 测试**：针对 `run.py` 编写集成测试，使用 `MockNodeFlowSDK` 验证数据流通断。

### 3. 文档完整性

每个节点都应有详细的 `README.md`，包含功能、端口、参数说明和使用示例。

### 4. 错误处理与日志

- 使用 `try-except` 捕获异常并记录日志，避免进程直接崩溃。
- 使用分级日志：`info` (生命周期), `debug` (数据流), `warning` (潜在问题), `error` (异常)。

### 5. 性能优化

- 避免在主循环中进行阻塞操作（IO、重计算）。
- 耗时计算应放入 L4 层的原子函数中优化。
- 定期输出统计日志，而不是每帧输出。

## 常见错误与修复

### 错误 1: node.yaml 格式错误 ❌

**症状**：运行时报错 `'list' object has no attribute 'items'`
**原因**：params 定义为列表而不是字典。

### 错误 2: 端口定义不在 ports 内 ❌

**症状**：节点未正确加载，输入/输出端口无法找到。
**修复**：确保 inputs/outputs 在 ports 字段下。

### 错误 3: 缺少 entrypoints 的 kind 字段 ❌

**症状**：节点启动失败。
**修复**：在 entrypoints 中添加 `kind: python`。

### 错误 4: 端口名称不匹配 ❌

**症状**：运行时找不到指定的端口。
**修复**：`run.py` 中的 `create_port` 名称必须与 `node.yaml` 完全一致。

### 错误 5: 循环依赖 ❌

**症状**：拓扑排序失败。
**修复**：检查 edges，确保图是有向无环图 (DAG)。

## 实践示例

### 示例: 简单的源节点（Joystick）

**run.py**:
```python
#!/usr/bin/env python3
import time
import math
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).parent.parent.parent))
from sdk.nodeflow_sdk import NodeFlowSDK

def main():
    with NodeFlowSDK(log_level="INFO") as sdk:
        sdk.logger.info(f"Joystick Mock 启动: {sdk.node_id}")

        mode = sdk.get_param('mode', 'sine')
        rate = float(sdk.get_param('update_rate_hz', 50))
        output_port = sdk.create_output_port('control_input')

        seq = 0
        start_time = time.time()

        try:
            while True:
                elapsed = time.time() - start_time

                if mode == 'sine':
                    linear = 1.5 * math.sin(2 * math.pi * elapsed / 10)
                    angular = 0.5 * math.cos(2 * math.pi * elapsed / 10)
                else:
                    linear = 1.5
                    angular = 0.0

                data = {
                    'timestamp': time.time(),
                    'seq': seq,
                    'linear_velocity': round(linear, 3),
                    'angular_velocity': round(angular, 3)
                }

                output_port.send(data)
                seq += 1
                time.sleep(1.0 / rate)

        except KeyboardInterrupt:
            sdk.logger.info("关闭")
```
